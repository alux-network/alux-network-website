Для ИИ-агентов

Платформа выполнения длядолгоживущих ИИ-агентов

В промышленной эксплуатации ИИ-агенты перестают быть простыми вызовами. Они ждут API и людей, координируются с другими агентами, несут ограниченные полномочия и нуждаются в записи произошедшего. ALUX предоставляет такой работе децентрализованную сервисную среду выполнения.

Среда выполнения на основе полномочий для ИИ-агентов в промышленной эксплуатации.

Единый жизненный цикл вместо хрупкой цепочки вызовов

Намерение

Машина агента RISC

Агентам нуженне только мозг

Агентам промышленного уровня нужны тело, мозг, иммунная система и социальный слой. Интеллект — лишь часть машины; среда выполнения должна поддерживать работу, ограничивать риски и связывать задачи разных организаций.

Агенты промышленного уровня должны соответствовать RISC. ALUX создаёт эту машину.

Спецификация RISC

R

Надёжный / Тело

между блоками · устойчивость · воспроизведение · воспроизводимость

Сохранение контекста между блоками и детерминированное воспроизведение обеспечивают воспроизводимость длительной работы при её возобновлении.

I

Интеллектуальный / Мозг

цикл LLM · память · инструменты · оркестрация

Циклы рассуждений, память, использование инструментов и оркестрация задач — области, в которых сегодня конкурирует большинство фреймворков агентов.

S

Защищённый / Иммунная система

объектное полномочие · политика · откат · аудит

Объектные полномочия, ограничения жизненного цикла, пути отката и данные для воспроизведения ограничивают эффекты, которые процесс может попытаться вызвать, и упрощают проверку зафиксированных результатов.

C

Связанный с другими / Социальный слой

делегирование между компаниями · нейтральная среда · сессионные типы

Спроектированные протоколы с сессионными типами дают агентам разных организаций возможность сотрудничать за пределами закрытых частных сред.

Как работа агентов живёт в ALUX

Рабочий процесс агента не нужно сводить к одному ограниченному вызову. Он может войти с заданной областью полномочий, разветвиться на конкурентную работу, приостановиться на внешнем ожидании, возобновиться в последующем блоке и оставить запись для подотчётности.

Ограниченное намерение

Ограниченный запрос поступает в среду выполнения

03

Выполнение приостанавливается в ожидании внешнего мира

04

Возобновление между блоками

Последующие блоки продолжают работу

05

Запись для подотчётности

История остаётся публичной

01

Поступает ограниченное намерение

Работа начинается с запроса, делегированного полномочия или намерения пользователя. Среда выполнения начинает с явных границ и контекста.

  • Полномочия передаются, но никогда не подделываются
  • Область действия определяет цель и границы
02

Конкурентные ветви

Подзадачи распределяются между агентами и сервисами, а не протискиваются через один линейный путь.

  • Пространство кортежей обеспечивает асинхронную координацию
  • Конкурентность подходит многошаговой работе агентов
03

Внешнее ожидание

Выполнение может приостанавливаться в ожидании ответа API или человека, срабатывания таймера, платежа или другого события реального мира.

  • Ожидание корректно приостанавливает выполнение
  • Состояние ожидания остаётся в среде выполнения
04

Возобновление между блоками

Когда внешний мир отвечает, процесс продолжается в последующем блоке с сохранёнными состоянием, памятью и разрешениями.

  • Непрерывность сохраняется в длительных задачах
  • История выполнения остаётся целой
05

Устойчивая запись

Записанные решения COMM и зафиксированные переходы состояния остаются воспроизводимыми для валидаторов и доступными системам аудита более высокого уровня.

  • Валидаторы воспроизводят тот же записанный результат выполнения
  • Основа для уровней управления и доверия

ALUX даёт работе агентов полный жизненный цикл: ограниченный вход, конкурентное выполнение, внешнее ожидание, продолжение между блоками и устойчивую запись.

Три слоя инфраструктуры агентов

Когда работа агентов действительно может оставаться активной, ALUX предоставляет ей три платформенных слоя: разрешения, координацию и подотчётность.

ALUX

Сервисная среда выполнения агентов

Среда выполнения, в которой агенты ждут, сотрудничают, обладают правами и остаются подотчётными.

Права

Инфраструктура прав на основе полномочий

Полномочия передаются неподделываемыми ссылками на каналы: они определяют, к чему процесс может обращаться, что вызывать, передавать дальше или сужать.

  • Управление полномочиями на основе встроенного OCAP
  • Делегирование и сужение
  • Основа для ограниченного доступа к инструментам
Сотрудничество

Инфраструктура координации агентов

Работа агентов требует сотрудничества. ALUX поддерживает конкурентную работу нескольких агентов, асинхронную координацию и процессы, продолжающиеся во времени.

  • Сообщения в пространстве кортежей для асинхронной координации
  • Ожидание и возобновление между блоками
  • Компонуемые сервисы и общие задачи
Подотчётность

Воспроизводимые доказательства выполнения

ReplayTrie записывает недетерминированные решения COMM для побитово точного детерминированного воспроизведения внутри среды ALUX; зафиксированные переходы состояния создают основу для аудита и управления более высокого уровня.

  • Результаты выполнения, воспроизводимые валидаторами
  • Зафиксированные переходы полномочий и состояния
  • Основа для уровней управления и безопасности
ALUX — не просто ИИ в блокчейне. Это инфраструктура разрешений, координации и прослеживаемой подотчётности агентов.

Внутри среды выполнения ALUX

ALUX объединяет сохраняемое выполнение, конкурентную координацию, явные полномочия и совместимость с EVM в одном слое среды выполнения.

Четыре основных механизма делают длительную работу агентов естественной частью платформы.

01

Непрерывность между блоками

Блок NПриостановкаБлок N+1

Транзакция может приостановиться на стыке и возобновиться в последующем блоке, когда разрешатся её зависимости.

02

Полномочия на основе встроенного OCAP

СоздательПолномочиеПроцесс

Процесс может использовать только созданные им или явно переданные ссылки; произвольные полномочия нельзя подделать опкодом.

03

Координация через пространство кортежей

ProduceПространство кортежейConsume

Процессы общаются через каналы produce и consume. Работа без совпадения ждёт; недетерминированные совпадения записываются для воспроизведения.

04

EVM через TSAC

EVMTSACTVM

Песочницы EVM сохраняют последовательное выполнение, а SLOAD, SSTORE и CALL обращаются к общим ресурсам через контракты-адаптеры пространства кортежей.

Вместе они сохраняют непрерывность, координацию и полномочия внутри среды выполнения, избавляя от их повторной реализации в коде приложения.
