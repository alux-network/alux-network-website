GLVM

전역 논리 가상 머신

여러 머신에 걸쳐 조율되는 하나의 논리 실행 계층

GLVM은 ALUX가 동시성 런타임을 기반으로 구축 중인 개발자용 실행 추상화입니다. 이 모델에 참여하는 각 머신에서는 TVM이 구체적인 실행 엔진을 제공하며, GLVM 모델은 실행 상태, 프로세스, 재현, 복제, 합의를 하나의 논리 계층으로 아우릅니다.

핵심 정의

머신마다 하나의 TVM, 하나의 논리 실행 모델로 조율

TVM은 한 머신에서 동작하는 바이트코드 실행 엔진입니다. GLVM은 이 모델에 참여하는 여러 TVM에 걸쳐 시스템 수준의 실행 추상화를 정의합니다. GLVM은 또 하나의 바이트코드 VM이 아닙니다. 개발자는 하나의 논리 모델을 대상으로 개발하고, 결정론적 재현, 실행 연속성, 복제, 최종 확정, 합의는 이 추상화 아래에서 조율됩니다.

TVM

튜플 공간 가상 머신(TVM)

ALUX의 구체적인 실행 엔진입니다. Tolang 바이트코드를 실행하고, 독립 프로세스를 채널과 COMM 이벤트로 조율하며, 결정론적 재현에 필요한 비결정적 선택을 기록합니다.

GLVM

핵심 요점

통합되는 것은 논리 실행 계층이지 물리 머신이 아니다

개발자는 하나의 동시성 실행 모델을 대상으로 개발하고, 런타임은 스케줄링·재현·권한 검사·복제·최종 확정을 처리합니다.

3계층 아키텍처

세 계층, 하나의 개발자용 실행 모델

물리 머신에서는 TVM이 실행됩니다. GLVM 아키텍처에서 이 엔진들은 하나의 공유 논리 실행 모델에 참여합니다. 미래의 World OS는 이 계층을 명시적 객체 권한으로 통제되는, 탐색 및 오케스트레이션 가능한 서비스로 구성합니다.

복합

여러 동시성 트랜잭션이 상위 수준의 원자적 목표를 공유합니다.

수직 원자성 · 코어 런타임블록 간 실행에서도 하나의 트랜잭션 컨텍스트를 유지
  1. 01 · 시작 한 번만 시작

    하나의 트랜잭션을 범위가 제한된 하나의 권한 집합으로 시작합니다.

  2. 02 · 일시 중단 부분 확정 없이 대기

    응답이나 채널 일치가 없으면 조기에 확정하지 않고 후속 실행을 보존합니다.

  3. 03 · 기록 선택 기록

    ReplayTrie는 해당 경로를 재현하는 데 필요한 비결정적 선택이나 인증된 응답을 기록합니다.

  4. 04 · 재개 같은 트랜잭션 이어가기

    일치하는 COMM 이벤트나 기록된 응답이 이후 블록에서 보존된 후속 실행을 깨웁니다.

  5. 05 · 최종 확정 커밋 또는 폐기

    최종 확정 경계에서는 조건을 충족한 상태가 커밋되고, 거부된 잠정 상태는 폐기됩니다.

핵심 실행 경로

TVM 동시성 실행 · COMM 대기와 재개 · ReplayTrie · 블록 간 연속 실행과 최종 확정

원자성 모델

잠정적인 중간 상태는 최종 확정 전까지 확정 상태가 되지 않습니다. 실패한 실행 경로는 나중에 보상 트랜잭션으로 복구하는 대신 폐기됩니다.

네이티브 오프체인 읽기

인증된 HTTPS GET은 실행을 일시 중지하고, 응답을 기록한 뒤 재현해 다시 실행할 수 있습니다. 다만 정보의 진실성은 여전히 데이터 소스가 결정하며, 되돌릴 수 없는 오프체인 부수 효과는 롤백 범위 밖에 있습니다.

수평 원자성

샤드 간 원자적 실행과 독립적인 외부 시스템과의 조합이 이 모델의 다음 확장을 이룹니다.

객체 권한 보안

작업에는 사용자의 ID 배지가 아니라 열쇠 하나를 전달

CEO–Bob 사례에서 신원 기반 접근은 CEO의 ID 배지가 나타내는 환경 권한을 작업 안으로 가져올 수 있습니다. 객체 권한을 사용하면 작업은 Bob의 기록을 가리키는 열쇠 하나만 받습니다. TVM은 런타임에 도달 가능한 경계를 강제합니다. 이미 존재하는 다른 객체를 가리키는 객체 권한 참조가 없다면, 작업은 그 객체를 지칭하거나 접근할 수 없습니다.

광범위한 신원 기반 권한

ID 배지가 관련 없는 접근 권한까지 작업에 가져옵니다

작업이 Bob만을 다루더라도 CEO의 ID 배지가 나타내는 신원 권한은 재무 정보와 Alice, Carol, Bob의 기록까지 포괄할 수 있습니다.

명시적 객체 권한

작업은 Bob의 기록을 가리키는 열쇠 하나를 받습니다

이 열쇠는 Bob의 기록을 식별하는 위조 불가능한 이름을 나타냅니다. 이미 존재하는 다른 객체를 가리키는 객체 권한 참조가 없다면, 작업은 그 객체를 지칭하거나 접근할 수 없습니다. TVM은 런타임에 이 경계를 검사합니다.

POLA · 최소 권한 원칙

모델의 안전장치는 위험한 동작을 줄일 수 있지만, 런타임에 최소 권한을 강제하는 것은 객체 권한 경계입니다. 에이전트가 Bob의 기록을 가리키는 열쇠만 가진다면, 침해의 영향은 그 객체 안에 머물며 CEO의 ID 배지가 나타내는 모든 신원 권한으로 번지지 않습니다.

용어

여기서 “열쇠”는 OCAP의 위조 불가능한 이름, 즉 객체 권한 참조를 시각적으로 나타냅니다. 암호학적 키가 아닙니다. 이 보장은 TVM 네이티브 환경에서 객체 권한을 매개로 이루어지는 상호작용에 적용됩니다. 호스팅된 EVM 권한과 외부 서비스에는 각각 별도의 통제가 필요합니다.

워크플로 탐색

신뢰 수준, 응답 시간, 데이터 지역성에 따라 실행 환경 선택

여러 회사가 참여하는 기기 수리를 생각해 보십시오. 에스크로에는 독립적인 검증이, 진단에는 탄력적으로 확장 가능한 컴퓨팅 자원이 필요하고, 로컬 접근은 기기 소유자가 승인해야 합니다. GLVM 모델에서는 권한을 명시적으로 유지하면서 각 작업을 신뢰 요건, 지연 시간, 데이터 경계에 맞는 실행 환경에 매핑합니다.

06

최종 확정 경계

BlockGit과 Block Merge는 검증 가능한 체인 측 결과를 수렴시킵니다. 모든 실행 환경을 하나의 원자적 커밋으로 확장하는 것이 GLVM의 다음 지향점입니다.

런타임 구조

GLVM 추상화를 뒷받침하는 아홉 가지 역량 영역

GLVM은 두 번째 바이트코드 VM이 아닙니다. TVM 실행, 객체 권한, 재현부터 BlockGit, 게스트 VM, 개발자 도구에 이르는 이 아홉 가지 아키텍처 관점은 GLVM의 논리 실행 모델을 뒷받침하는 역량 체계를 보여 줍니다.

  1. 01
    바이트코드 VM코어 런타임

    TVM · 튜플 공간 · COMM

    구체적인 동시성 엔진이 바이트코드를 실행하고, 독립 프로세스들이 채널을 통해 데이터와 후속 실행을 교환할 수 있게 합니다.

  2. 02
    보안코어 런타임

    네이티브 객체 권한

    위조 불가능한 참조로 접근 가능한 권한을 명시하고, 런타임이 최소 권한 경계를 강제할 수 있게 합니다.

  3. 03
    원자성코어 런타임

    블록 간 원자적 실행

    실행 컨텍스트는 블록을 건너 일시 중지되고, 보존된 후속 실행에서 재개되어 지연된 최종 확정 경계에 도달할 수 있습니다.

  4. 04
    최종성코어 런타임

    BlockGit · fringe · merge

    블록 DAG, 결정론적 리더 순환, 병합 규칙을 통해 영구 리더 없이 체인 측 동시성 작업을 수렴시킵니다.

  5. 05
    재현코어 런타임

    ReplayTrie · 실행 추적

    기록된 비결정적 선택과 실행 추적을 통해 검증자는 승인된 경로를 재현할 수 있습니다.

  6. 06
    네트워크코어 런타임

    피어·검증자 네트워크

    노드 계층은 실행 추상화 아래에서 제안, 블록, 상태 증거, 검증자 간 조율을 전달합니다.

  7. 07
    언어코어 런타임

    Tolang → tolangc → .tox

    Tolang은 동시성 프로세스를 기술하고, 컴파일러는 소스를 TVM에서 실행 가능한 바이트코드로 변환합니다.

  8. 08
    게스트 VMEVM 코어 · WASM 로드맵

    EVM 호스트 · WASM 로드맵

    EVM은 TSAC 방식의 조율을 통해 상태를 유지하는 게스트로 실행됩니다. WASM은 이기종 VM으로의 확장을 이어 갑니다.

  9. 09
    도구개발자 도구

    컴파일러 · LSP · 플레이그라운드

    컴파일러, LSP, 플레이그라운드, 테스트 스위트, 진단 도구가 실행 모델을 개발자 워크플로로 연결합니다.

개발 방향

코어 런타임이 구체화되고 있으며, GLVM은 여러 환경으로 확장 중

GLVM은 ALUX의 동시성 체인 런타임을 기반으로 확장됩니다. 프라이빗 클라우드는 다음 통합 대상이며, 클라이언트 기기 실행과 샤드 간 실행은 로드맵 단계입니다. 아래 구성도에서는 코어 런타임, 현재 확장 중인 실행 환경, 다음 아키텍처 지향점을 구분해 보여 줍니다.
