Runtime Lab

Parallel / Nebenläufig / Kombinierbar

ALUX unterstützt wiederholbare Langtransaktionen: Unabhängige Aufgaben laufen gleichzeitig, und Transaktionen koordinieren sich über Nachrichten. Das Buchungsszenario veranschaulicht das Zielmodell, bei dem zusammengehörige systemübergreifende Effekte als ein atomares Ergebnis abgeschlossen werden.

PositionierungDezentrale nebenläufige Runtime
AusführungAusführen, interagieren, warten, abschließen
GrenzeAbläufe mit begrenzten Capabilities

Der einfache Unterschied

Drei Begriffe, drei ganz unterschiedliche Aufgaben der Runtime

Parallelität führt unabhängige Transaktionen gleichzeitig aus. Nebenläufigkeit ermöglicht Interaktion über Kanäle: Eine Transaktion kann auf eine passende Nachricht einer anderen warten und anschließend fortfahren. Komponierbarkeit verbindet Zustandsübergänge verschiedener Systeme zu einem überprüfbaren atomaren Übergang.

In der aktuellen ALUX-Runtime kann unabhängige Arbeit parallel laufen, Transaktionen koordinieren sich über Nachrichten und Ausführungen können blockübergreifend fortgesetzt werden. Atomare Komposition über unabhängige Systeme hinweg bleibt ein Architekturziel.

Parallel

Flug, Hotel, Transfer und Versicherung
gleichzeitig suchen

Was es bedeutet
Parallele Ausführung bedeutet, dass unabhängige Aufgaben gleichzeitig laufen. Ein Reise-Agent kann Flüge, Zimmer, Transfers und Versicherungen suchen, ohne eine Suche hinter einer anderen warten zu lassen.
Wie ALUX es umsetzt
Parallele Ausführung ist Teil des nativen Prozesskalküls von ALUX: Transaktionen teilen keinen Speicher, und jede Interaktion ist auf Tuple-Space-Kanäle beschränkt. Daher schreiten unabhängige Transaktionen auf getrennten TVM-Spuren voran; Block Merge löst Zustandsüberschneidungen beim Commit auf.
Was es ermöglicht
Mehr unabhängige Arbeit wird in derselben Zeit erledigt. Parallelität allein ermöglicht diesen Aufgaben jedoch weder den Nachrichtenaustausch noch das Warten und Fortsetzen einer Langtransaktion.

Parallelität findet mehrere Antworten zugleich. Sie lässt diese Aufgaben nicht miteinander interagieren.

Nebenläufig

Eine Buchung wartet auf Verfügbarkeit
und wird mit der Antwort fortgesetzt

Was es bedeutet
Wenn Aufgaben miteinander interagieren, beginnt Nebenläufigkeit. Eine Buchung kann eine Wartebedingung in einem Kanal hinterlegen; ein Hoteldienst kann sie später durch die passende Verfügbarkeitsnachricht erfüllen.
Wie ALUX es umsetzt
Der wartende Consume wird als Ressource im Tuple Space gespeichert. Ein Produce einer anderen Transaktion gleicht ihn ab und löst ein COMM-Ereignis aus. Dieses startet die Fortsetzung und wechselt den Execution Context von Inactive zurück zu Running. Sind mehrere Abgleiche möglich, zeichnet ReplayTrie das ausgewählte COMM für die deterministische Wiederholung auf.
Was es ermöglicht
Ein Reise-Agent kann eine Langtransaktion über mehrere Blöcke am Leben halten: Er wartet auf Zimmerverfügbarkeit, eine API-Antwort oder eine Nutzerentscheidung und fährt anschließend fort, ohne unabhängige Arbeit zu blockieren.

Nebenläufigkeit macht aus einer Antwort den nächsten Schritt: Durch den Nachrichtenabgleich entsteht eine neue Fortsetzung, statt eine angehaltene Spur lediglich neu zu starten.

Kombinierbar

Zimmer und Zahlung
werden gemeinsam bestätigt

Was es bedeutet
Komposition ist keine gewöhnliche Bündelung. In diesem Beispiel sollen Zimmerreservierung und Zahlungsautorisierung gemeinsam übernommen werden – oder beide gar nicht.
Wie ALUX es umsetzt
Die aktuelle Runtime bietet Tuple-Space-Koordination, begrenzte OCAP-Referenzen, blockübergreifende Fortsetzung, ReplayTrie und Block Merge. Die durchgängige atomare Komposition unabhängiger externer Systeme bleibt ein Entwurfsziel, das auf diesen Grundbausteinen aufbaut.
Was es ermöglicht
Das gewünschte Ergebnis verhindert halbfertige Buchungen – etwa eine Belastung ohne Zimmer oder ein reserviertes Zimmer ohne Zahlung.

Das Zielmodell für Komposition liefert Systemen ein gemeinsames Alles-oder-nichts-Ergebnis; Nebenläufigkeit trägt die Nachrichten, die zu diesem gemeinsamen Commit führen.

Runtime-Pfad

Was einen Dienst am Laufen hält

Ein lang laufender Dienst bleibt konsistent, weil jeder Schritt ausgeführt werden, interagieren, explizite Berechtigungen übertragen, deterministisch wiederholt und über einen überprüfbaren atomaren Pfad abgeschlossen werden kann.

Ausführen

Lebenszyklus eines TVM-Prozesses

Ein Prozess kann sich verzweigen, in einem Block warten und in einem späteren Block fortgesetzt werden, ohne seinen lokalen Ausführungskontext neu aufzubauen.

Interagieren

Tuple Space + COMM

Ein wartender Consume trifft auf das Produce einer anderen Transaktion. Der Abgleich aktiviert die Fortsetzung, während unabhängige Arbeit weiterläuft.

Berechtigen

OCAP-Grenzen

Fälschungssichere Capability-Referenzen werden explizit übergeben, sodass jeder Schritt nur die nötigen Berechtigungen erhält; eine Identität bringt nicht automatisch sachfremde Rechte in den Geltungsbereich.

Wiederholen

ReplayTrie

Nur die relevanten nichtdeterministischen COMM-Entscheidungen werden aufgezeichnet, sodass Validatoren dieselbe Ausführung reproduzieren können.

Abwickeln

BlockGit + Block Merge

Nebenläufige Arbeit gelangt in überprüfte Fringes. Dort werden Überschneidungen vor der Finalisierung als akzeptiert, abgelehnt oder unentschieden eingestuft.

Nächste Ebene

Eine logische Runtime über viele Umgebungen hinweg

Runtime Lab zeigt die aktuelle parallele und nachrichtenbasierte Ausführung und veranschaulicht anschließend das Zielmodell atomarer Komposition. GLVM beschreibt die umfassendere Architektur, mit der sich dieses logische Modell über Blockchain-Nodes, Cloud-Dienste und persönliche Geräte hinweg erweitern lässt.

Warum es wichtig ist

Keine schnelleren Blöcke. Lang laufende Dienste.

Parallelität übernimmt unabhängige Ausführung. Nebenläufigkeit ermöglicht nachrichtenbasierte Interaktion sowie Warten und Fortsetzen. ALUX implementiert diese Runtime-Grundlagen bereits heute und arbeitet auf atomare Komposition über Systemgrenzen hinweg hin.

Nur parallel

Mehr Durchsatz, aber keine Transaktionsabhängigkeiten oder Nachrichtenabgleiche.

Nur nebenläufig

Transaktionen können miteinander interagieren und warten, aber systemübergreifende Effekte werden möglicherweise weiterhin getrennt abgeschlossen.

Nur kombinierbar

Es gibt eine atomare Grenze, doch ohne Interaktion und Warten lassen sich darin keine lang laufenden Abhängigkeiten abbilden.
