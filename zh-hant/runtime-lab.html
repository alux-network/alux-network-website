Runtime Lab

平行、併發、組合

ALUX 支援可重播的長交易：獨立任務可以同時推進，交易則透過訊息協作。預訂場景示範的是目標模型——讓相關的跨系統狀態變化作為一個原子結果結算。

定位去中心化併發執行階段
執行執行、互動、等待、結算
邊界能力約束下的工作流程

先分清三件事

三個詞看似相近，卻代表三種截然不同的執行階段工作

平行讓互不依賴的交易同時執行。併發讓交易透過通道互動：一筆交易可以等待另一筆交易發來匹配訊息，再繼續執行。組合把不同執行系統中的狀態轉移放進同一個結算邊界，使它們作為一次可審計的原子狀態轉移完成結算。

在目前 ALUX 執行階段中，獨立任務可以平行推進，交易透過訊息協作，執行也能跨區塊恢復。獨立系統之間的原子組合仍屬於架構目標。

平行

航班、酒店、接送和保險
同時查詢

它是什麼意思
平行指多項互不依賴的工作同時執行。旅行AI Agent可以同時查詢航班、房間、接送和保險，不必讓一項查詢排在另一項後面。
ALUX 如何做到
平行執行是 ALUX 程序演算的原生能力：交易不共享記憶體，任何互動都只能透過元組空間通道發生。互不依賴的交易因此可以在不同 TVM 執行軌道上推進，提交時若出現狀態重疊，再由 Block Merge 裁決。
它能做什麼
同樣時間裡能完成更多獨立工作，但單靠平行，既不能讓這些工作交換訊息，也不能讓一筆長交易等待後繼續。

平行可以同時得到多項結果，但不會讓這些任務彼此互動。

併發

預訂等待房態，
收到回覆後繼續

它是什麼意思
併發從工作之間發生互動開始。預訂可以在通道中留下等待條件，酒店服務稍後發回匹配的房態訊息，預訂再繼續。
ALUX 如何做到
等待方的接收要求（consume）會作為等待資源保存在元組空間中；另一筆交易發出（produce）匹配資料後觸發 COMM 事件，產生等待方的後續執行（continuation），並讓執行上下文從非活動狀態恢復為執行狀態。當存在多個候選匹配時，ReplayTrie 記錄實際選中的 COMM，供驗證者確定性重播。
它能做什麼
旅行AI Agent可以讓一筆長交易跨區塊等待房態、API 回覆或使用者決定，並在條件滿足後繼續執行，同時不阻塞無關工作。

併發把一次回覆變成下一步執行：訊息匹配會產生新的後續執行，而不是讓停住的軌道原地重啟。

組合

房間鎖定與付款
共同確認

它是什麼意思
組合不是把多項工作簡單打包。這個示例的目標，是讓房間鎖定與付款授權要麼共同提交，要麼都不提交。
ALUX 如何做到
目前執行階段已經提供元組空間協作、限定範圍的 OCAP 引用、跨區塊後續執行、ReplayTrie 與 Block Merge。基於這些原語，在彼此獨立的外部系統之間實作端到端原子組合，仍屬於設計目標。
它能做什麼
預期結果是避免出現只扣款卻沒有房間，或只鎖房卻沒有完成付款的半成品預訂。

目標組合模型讓不同系統得到一個全有或全無的結果；併發負責傳遞共同提交前的訊息。

執行路徑

是什麼讓服務持續執行

長時間執行的服務之所以保持一致，是因為每一步都能執行、互動、攜帶顯式權限、進行確定性重播，並沿一條可驗證的原子路徑完成結算。

執行

TVM 處理程序生命週期

處理程序可以分叉，在一個區塊中等待，並在後續區塊恢復，而不必重新啟動本地執行上下文。

互動

元組空間 + COMM

等待中的取用（Consume）與另一筆交易的寫入（Produce）相匹配；匹配會喚醒後續執行，而無關工作繼續推進。

授權

OCAP 權限邊界

不可偽造的能力引用被顯式傳遞，讓每一步只獲得所需權限；身份不會自動把無關權限帶入目前環境。

重播

ReplayTrie

只記錄真正影響結果的非確定性 COMM 選擇，使驗證者能夠復現同一段執行。

結算

BlockGit + Block Merge

併發工作進入經過驗證的 Fringe；相互重疊的結果會在最終確認前被判定為接受、拒絕或待定。

為什麼重要

不是更快的區塊，而是持續執行的服務

平行負責推進彼此獨立的任務，併發負責訊息驅動的互動以及等待與恢復。ALUX 目前已實作這些執行階段基礎，並正在面向跨系統原子組合繼續建設。

只有平行

吞吐更高，但沒有交易依賴與訊息匹配。

只有併發

交易可以互動和等待，但跨系統結果仍可能分別結算。

只有組合

存在原子邊界，但沒有互動與等待，就承載不了持續執行的依賴關係。
