ALUX Network

グローバル VM を構築する

パブリックブロックチェーン、プライベートクラスター、スマートフォンやブラウザなど、あらゆる環境で動くひとつの論理仮想マシンを想像してください。状態、スレッド、レプリケーション、コンセンサスといった基盤の違いは、共通の抽象化の下に隠されます。開発者が書く並行プログラムはひとつだけ。実行場所はアーキテクチャ上の制約ではなく、設定で選べます。各部分はひとつのアトミックな結果として、まとめてコミットされます。これが Virtual Machine Abstraction であり、ALUX が構築しているものです。

目標モデルでは、参加するすべてのシャードの更新を単一のトランザクション境界内でステージングします。いずれかのシャード内呼び出しが失敗すれば、ステージング済みの更新は観測可能になる前にすべて破棄されます。クロスシャード実行は現行ランタイムには未実装です。

部分的にコミットされた状態を Saga 補償で修復する負担をアプリケーションに課さず、水平スケールを実現します。

仮想マシン抽象化ALUX ランタイム

GLVM は、TVM の並行実行、OCAP のネイティブサポート、ブロック横断アトミック性、BlockGit ファイナリティを一つの論理実行レイヤーに統合します。

一つの論理実行レイヤー

TVM 実行、OCAP のネイティブサポート、クロスブロックのコミットロジック、BlockGit ファイナリティが、ひとつのランタイム抽象化の中で統合されます。

このアーキテクチャは、チェーン、プライベートクラウド、将来のクライアントデバイス実行にわたって、一つの開発者モデルを保ちます。

ユースケース

ALUX で構築できるもの

待機中もコンテキストを保持し、並行処理を調整し、単一の結果として確定するワークフローを構築できます。現行機能とロードマップ上の目標は分けて表示しています。

01

オンチェーンで長時間稼働する AI エージェント

ワークフローは複数のエージェントを並行して起動します。Claude API を呼び出すエージェントもあれば、ユーザー入力を待つ処理もあります。ワークフローが約30分間続く場合でも、メインエージェントはすべての分岐が完了した後にのみ処理を続行します。Claude API とユーザー入力との接続はアプリケーションレイヤーが担い、ALUX は永続的な fork、wait、join、ケイパビリティの受け渡し、リプレイ可能な実行を提供します。

3つの取引所からの BTC 価格集約

03

クロスシャード・アトミック実行

Shard A の contract a は、Shard B の contract b が管理するチケットの支払いをステージングします。チケットがすでに販売済みで b が失敗した場合、a の支払いはロールバックされます。両方の処理が成功した場合に限り、支払いとチケットの所有権が一緒にコミットされ、他のトランザクションから部分的な状態が見えることはありません。クロスシャード・アトミック実行はロードマップ上の目標であり、現時点で稼働中の機能ではありません。

ALUX では普通のスマートコントラクトにできない何が可能になりますか？
ALUX はスマートコントラクトモデルを、長期実行ジョブ向けの分散型 Durable Execution Engine へ拡張します。ワークフローは並行プロセスを実行し、ブロックをまたいで一時停止し、外部ツールや人を待ち、再開して結果を join できます。その間も中途半端な状態は露出しません。ランタイムが仲介する外部チャネルにより、個別のオラクルとリレイヤーを組み合わせることなく、対応するオフチェーンサービスと連携できます。さらに同じアトミックモデルを水平に拡張し、クロスシャード効果をまとめてコミットまたは中止できるよう設計されています。クロスシャード実行は引き続きロードマップ上にあります。
なぜ ALUX は AIエージェント向けなのですか？
オンチェーンエージェントは本質的に長期トランザクションです。LLM やツールの呼び出しには時間がかかり、人の応答を待つにも時間が必要です。このワークフローを即時に完了する 1 ブロックの呼び出しへ押し込むことはできません。ALUX なら実行コンテキストを保持し、一時停止し、入力が届いた時点で再開し、複数のエージェントを並行して調整し、再現可能な実行によって確定できます。
ALUX はただの高速な L1 ですか？
いいえ。高速な L1 が加速するのは、ひとつのブロック内で完結する単発の状態更新という、同じ抽象化です。ALUX は、待機、再開、複数チャネルにまたがる join、または最初に準備が整ったチャネルの select が可能な長期トランザクション（Long Transaction）のための分散型並行ランタイムです。その状態更新は、もはやブロック境界に制約されません。GLVM アーキテクチャ——Virtual Machine Abstraction（仮想マシン抽象化）——により、同じ論理トランザクションをブロック境界の先へ、シャード境界やシステム境界にまで拡張できるよう設計されています。
他のチェーンもクロスブロックトランザクション対応をうたっています。ALUX は何が違うのですか？
鍵となるのはアトミック性です。

補償 / Saga: commit → commit → ✗ fail → run compensating undo
各ステップはローカルでコミットされるため、中間状態が可視化されます。補償処理も失敗する可能性があり、外部への副作用を常に取り消せるとは限りません。これは結果整合性です。ICP や Rialo を含む一部の非同期チェーンは、このモデルに依存しています。実装は容易ですが、より強い ACID 保証を必要とするアプリケーションには適しません。

ALUX の all-or-nothing: stage → stage → ✗ fail → discard everything
トランザクション全体がコミットされるまで、何もコミットされません。中止時には未コミットの効果が破棄され、部分状態が可視化されることはありません。これが、ブロック高をまたぐ真の ACID アトミック性です。
ALUX は長期トランザクションをどう決定論的に保つのですか？
ReplayTrie は、実行に影響する非決定的な COMM の選択を記録します。これにより、ALUX ランタイム内でビット単位に完全一致する決定論的リプレイが可能になり、バリデータは同じ実行結果を再現できます。
オブジェクトケイパビリティ（OCAP）とは何ですか？
オブジェクト・ケイパビリティ（OCAP）は、コードがリソースにアクセスするためには、そのリソースへの参照（ケイパビリティ）を明示的に付与されなければならない、というセキュリティモデルです。OCAP システムでは、同じオブジェクト参照がリソースを特定する役割（designation）と、その利用を許可する役割（authorization）の両方を担います。
OCAP が、より強力でコンポーザブルなセキュリティモデルであるのはなぜですか？
オブジェクト・ケイパビリティ（OCAP）がより強力なセキュリティモデルである理由は、権限をグローバルな ID やアクセス制御リストではなく、明示的で偽造不可能なケイパビリティとして表現する点にあります。「指定がそのまま権限付与となる（designation is authorization）」という原則に従い、ケイパビリティを保持することが、対象リソースの特定と利用許可の両方を意味します。これによりアンビエント権限を排除し、攻撃対象領域を縮小できます。ケイパビリティは安全に委譲・制限・失効できるため、セキュリティポリシーは中央集権的な権限システムに分散するのではなく、関係するオブジェクトに局所化されます。その結果、OCAP は自然に組み合わせ可能となり、最小権限の原則を維持したまま、独立して安全なコンポーネントから複雑なアプリケーション、スマートコントラクト、AI エージェントのワークフローを構築できます。
ALUX が OCAP をネイティブサポートするとは、どういう意味ですか？
ALUX のタプルスペース仮想マシン（TVM）は、オブジェクト・ケイパビリティ（OCAP）モデルをバイトコードレベルで直接実装しています。命令セットには、任意のオブジェクト参照を偽造または構築する操作が存在しないため、ケイパビリティは明示的な委譲によってのみ取得できます。これにより、すべての権限が偽造不可能であり、かつ明示的に移転されることが保証されます。
既存のスマートコントラクト開発者も使えますか？
TVM は分離されたサンドボックス内で EVM バイトコードを実行するため、ほとんどの EVM コントラクトは最小限の変更で ALUX へ移行できます。また ALUX は、一般的に利用される一連の eth_* JSON-RPC メソッドを通じて、Ethereum 互換のビューを提供します。
