GLVM

グローバル論理仮想マシン

多数のマシンにまたがって協調する、ひとつの論理実行レイヤー

GLVM は、ALUX が並行ランタイムを基盤として構築を進める、開発者向けの実行抽象化です。このモデルに参加する各マシンでは TVM が具体的な実行エンジンを担い、GLVM モデルは実行状態、プロセス、リプレイ、レプリケーション、コンセンサスを一つの論理レイヤーにまとめます。

物理モデルマシンごとに一つの TVM
論理モデルその上に一つの GLVM
展開方向チェーンからクラウド、そしてデバイスへ

中核となる定義

各マシンに一つの TVM、単一の論理実行モデルで協調

TVM は、一台のマシン上で動作するバイトコード実行エンジンです。GLVM は、このモデルに参加する複数の TVM にまたがるシステムレベルの実行抽象化を定義します。GLVM は別のバイトコード VM ではありません。開発者は一つの論理モデルを対象とし、その抽象化の下で決定論的リプレイ、実行の継続、レプリケーション、確定処理、コンセンサスが協調されます。

TVM

タプル空間仮想マシン（TVM）

ALUX の具体的な実行エンジンです。Tolang バイトコードを実行し、独立したプロセスをチャネルと COMM イベントで協調させ、決定論的リプレイに必要な非決定的選択を記録します。

一台のマシン内で動く具体的なエンジン
GLVM

グローバル論理仮想マシン（GLVM）

GLVM は、このモデルに参加する複数の TVM にまたがる開発者向けの論理モデルを定義します。実行状態とプロセスに対する単一の境界を提供し、リプレイ、レプリケーション、確定処理、コンセンサスはその抽象化の下で処理されます。

要点

統一されるのは論理実行レイヤーであり、物理マシンではない

開発者は一つの並行実行モデルを対象とし、ランタイムがスケジューリング、リプレイ、ケイパビリティ検査、レプリケーション、確定を担います。

3層アーキテクチャ

三つのレイヤー、一つの開発者向け実行モデル

物理マシンでは TVM が動作します。GLVM アーキテクチャでは、それらのエンジンが一つの共有論理実行モデルに参加します。将来の World OS は、そのレイヤーを明示的なケイパビリティによって統制される、探索・オーケストレーション可能なサービスとして編成します。

実行と原子性

トランザクションはブロックをまたいで待機し、最後に一つの結果として確定できる

実行は、逐次・並列の処理から、通信し、待機し、再開できる並行プロセスへと発展します。複合実行はこのモデルを拡張し、複数の並行トランザクションが上位の確定境界を共有できるようにします。ブロックをまたぐ連続性が、その方向を支える垂直方向の基盤です。

複合

複数の並行トランザクションが、上位の原子性目標を共有します。

垂直方向の原子性 · コアランタイムブロック横断実行でも、一つのトランザクション・コンテキストを保つ
  1. 01 · 開始 一度だけ開始

    一つのトランザクションを、範囲を限定した一組のケイパビリティとともに開始します。

  2. 02 · 中断 部分確定せずに待機

    応答またはチャネルの一致が得られない場合、早期に確定せず、継続を保持します。

  3. 03 · 記録 選択を記録

    ReplayTrie は、その経路を再現するために必要な非決定的選択または認証済み応答を記録します。

  4. 04 · 再開 同じトランザクションを継続

    一致する COMM イベントまたは記録済み応答が、後続ブロックで保持された継続を起動します。

  5. 05 · 確定 コミットまたは破棄

    確定境界では、条件を満たす状態がコミットされ、却下された暫定状態は破棄されます。

コア実行パス

TVM の並行実行 · COMM による待機と再開 · ReplayTrie · ブロック横断の継続と確定

原子性モデル

暫定的な中間状態は、確定処理が完了するまで確定状態にはなりません。失敗した実行パスは、後から補償トランザクションで修復するのではなく破棄されます。

ネイティブなオフチェーン読み取り

認証済み HTTPS GET は実行を一時停止させ、応答を記録し、リプレイして再開できます。ただし、情報の真偽は引き続きデータソースが決め、不可逆なオフチェーン副作用はロールバックの対象外です。

水平方向の原子性

シャード間の原子的実行と、独立した外部システムとの合成が、このモデルの次の拡張を形づくります。

オブジェクト・ケイパビリティ・セキュリティ

タスクに渡すのは一本の鍵、ユーザーの ID バッジではない

CEO と Bob の例では、アイデンティティベースのアクセスによって、CEO の ID バッジが表すアンビエント権限までタスクに持ち込まれることがあります。オブジェクト・ケイパビリティでは、タスクが受け取るのは Bob の記録を指す一本の鍵だけです。TVM は実行時に到達可能な境界を強制します。既存の別のオブジェクトへのケイパビリティ参照がなければ、タスクはそのオブジェクトを名指しすることも、そこへ到達することもできません。

アイデンティティに基づく広範な権限

ID バッジが無関係なアクセス権限までタスクに持ち込む

タスクが Bob だけに関するものであっても、CEO の ID バッジが表すアイデンティティ権限は、財務情報に加え、Alice、Carol、Bob の記録すべてに及ぶ可能性があります。

明示的なオブジェクト・ケイパビリティ

タスクが受け取るのは Bob の記録を指す一本の鍵

この鍵は、Bob の記録を識別する偽造不能な名前を表します。既存の別のオブジェクトへのケイパビリティ参照がなければ、タスクはそのオブジェクトを名指しすることも、そこへ到達することもできません。TVM は実行時にその境界を検証します。

POLA · 最小権限の原則

モデル側の安全対策は危険な挙動を減らせますが、実行時に最小権限を強制するのはケイパビリティ境界です。エージェントが Bob の記録を指す鍵しか持たない場合、侵害の影響はそのオブジェクト内に留まり、CEO の ID バッジが表すアイデンティティ権限全体には広がりません。

用語

ここでいう「鍵」は、OCAP における偽造不能な名前、すなわちケイパビリティ参照を視覚的に表したものです。暗号鍵ではありません。この保証が適用されるのは、TVM ネイティブでケイパビリティを介した相互作用です。ホスト型 EVM の権限や外部サービスには、それぞれ独自の制御が必要です。

ワークフロー探索

信頼性、応答時間、データの局所性に応じて実行環境を選ぶ

複数企業にまたがるデバイス修理を考えてみましょう。エスクローには独立した検証、診断には需要に応じて拡張できる計算資源が必要で、ローカルアクセスはデバイス所有者が承認する必要があります。GLVM モデルでは、権限を明示したまま、各タスクを信頼要件、レイテンシー、データ境界に適した実行環境へ割り当てます。

ランタイムの構造

GLVM 抽象レイヤーを支える九つのケイパビリティ領域

GLVM は、第二のバイトコード VM ではありません。TVM 実行、オブジェクト・ケイパビリティ、リプレイから BlockGit、ゲスト VM、開発者ツールまで、これら九つのアーキテクチャ上の観点が、GLVM の論理実行モデルを支えるケイパビリティ体系を示します。

  1. 01
    バイトコード VMコアランタイム

    TVM · タプルスペース · COMM

    具体的な並行実行エンジンがバイトコードを実行し、独立したプロセス同士がチャネルを介してデータと継続を交換できるようにします。

  2. 02
    セキュリティコアランタイム

    ネイティブなオブジェクト・ケイパビリティ

    偽造不可能な参照によって到達可能な権限を明示し、ランタイムが最小権限の境界を強制できるようにします。

  3. 03
    原子性コアランタイム

    ブロック横断のアトミック実行

    実行コンテキストはブロックをまたいで一時停止し、保持された継続から再開して、延期された確定境界に到達できます。

  4. 04
    ファイナリティコアランタイム

    BlockGit · fringe · merge

    ブロック DAG、決定論的なリーダー交代、マージ規則により、恒久的なリーダーを置かずにチェーン側の並行処理を収束させます。

  5. 05
    リプレイコアランタイム

    ReplayTrie · 実行トレース

    記録された非決定的選択と実行トレースにより、バリデータは受理された経路を再現できます。

  6. 06
    ネットワークコアランタイム

    ピア／バリデータ・ネットワーク

    ノードレイヤーは実行抽象化の下で、提案、ブロック、状態証拠、バリデータ間の協調を伝達します。

  7. 07
    言語コアランタイム

    Tolang → tolangc → .tox

    Tolang は並行プロセスを記述し、コンパイラがソースを TVM で実行可能なバイトコードへ変換します。

  8. 08
    ゲスト VMEVM コア · WASM ロードマップ

    EVM ホスト · WASM ロードマップ

    EVM は、TSAC 方式の協調を通じてステートフルなゲストとして動作します。WASM は、異種 VM への展開をさらに広げます。

  9. 09
    ツール群開発者向けツール

    コンパイラ · LSP · プレイグラウンド

    コンパイラ、LSP、プレイグラウンド、テストスイート、診断機能が、実行モデルを開発者のワークフローへつなぎます。
